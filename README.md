# DB Uni Site: отчеты по уязвимостям

В репозитории собраны отчеты по найденным и исправленным уязвимостям учебного веб-приложения `DB_SEC_SITE`. Каждый отчет лежит в отдельной папке, содержит описание результата атаки, способ обнаружения, причину уязвимости, исправление, фрагменты кода до и после исправления, а также демонстрационные gif/скриншоты.

## Структура отчетов

| Раздел | Что описано |
| --- | --- |
| [1) обход аутентификации](<1) обход аутентификации/README_1v.md>) | Повышение роли пользователя через подмену поля `roleName` в форме профиля и исправление через запрет обновления роли из пользовательского маршрута. |
| [2) извлечение данных через UNION](<2) извлечение данных через UNION /README_2v.md>) | SQL-инъекция в поиске клиентов через `UNION SELECT` и исправление через параметризованный запрос. |
| [3) error-based инъекции](<3) error-based инъекции/README_3v.md>) | Получение сведений о базе через сообщения PostgreSQL и исправление отчета через безопасные параметры фильтрации. |
| [4) blind sql](<4) blind sql/README_4v.md>) | Blind SQL-инъекция в пользовательском отчете, где результат угадывался по наличию строк, и исправление через отказ от произвольного `WHERE`-фрагмента. |
| [5.1) получение данных отчета](<5) прочее/5.1) получение данных отчета/README_5.1v.md>) | Получение чужих данных отчета через подмену условия фильтрации и исправление через разрешенный фильтр и параметризованный SQL. |
| [5.2) изменение чужого профиля](<5) прочее/5.2) изменение чужого профиля/README_5.2v.md>) | IDOR-уязвимость при изменении профиля другого пользователя и исправление через сравнение id из URL с id текущей сессии. |

## Что есть внутри отчетов

- описание результата уязвимости;
- шаги, которыми уязвимость была найдена;
- payload или пример запроса, если он использовался;
- причина проблемы в коде или SQL-логике;
- фрагменты кода до и после исправления;
- gif/скриншоты с демонстрацией и подтверждением исправления;
- вывод с краткой формулировкой, почему исправление закрывает проблему.

Все ссылки на изображения и gif внутри отчетов оставлены относительными, чтобы материалы корректно открывались на GitHub.
